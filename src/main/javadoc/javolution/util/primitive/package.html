Provides high-performance, zero-boxing primitive collections including resizable tables ({@code FastTable}), open-addressing hash sets ({@code FastSet}), and open-addressing primitive hash maps ({@code FastIntMap}, {@code FastLongMap}, {@code FastIntObjectMap}, {@code FastLongObjectMap}) for Java primitive types, avoiding object creation and auto-boxing overhead.

Overview:

All primitive collections extend {@link javolution.util.primitive.FastPrimitiveCollection FastPrimitiveCollection} and all primitive maps extend {@link javolution.util.primitive.FastPrimitiveMap FastPrimitiveMap}; both hierarchies implement {@link javolution.lang.Reusable Reusable} for zero-GC object recycling:

Migration from the pre-6.0 API:

Version 6.0 removes the former {@code FastArrayList} classes in favor of {@code FastTable}, and replaces {@code FastPrimitiveList} with {@code FastPrimitiveCollection}. This is an intentional source and binary compatibility break: applications must update imports and recompile. No deprecated aliases, adapters, or duplicate compatibility classes are provided.

3. Open-Addressing Primitive Maps:

Maps from primitive int and long keys to all 8 primitive value types and generic object values, serving as O(1) average-time real-time counterparts to Android {@code SparseArray}, {@code SparseArray}, and {@code LongSparseArray}. Absent-key lookups and removals return type-default values (or caller-specified fallbacks), while {@code putIfAbsent}/{@code putKeyIfAbsent}, {@code removeKey}, and {@code removeEntry} distinguish missing keys explicitly. Because entries are stored in open-addressing hash tables rather than sorted arrays, iteration order is unspecified and index-based accessors ({@code keyAt}/{@code valueAt}) are not provided.

  • int-keyed maps: {@link javolution.util.primitive.FastIntBooleanMap FastIntBooleanMap}, {@link javolution.util.primitive.FastIntByteMap FastIntByteMap}, {@link javolution.util.primitive.FastIntCharMap FastIntCharMap}, {@link javolution.util.primitive.FastIntShortMap FastIntShortMap}, {@link javolution.util.primitive.FastIntIntMap FastIntIntMap}, {@link javolution.util.primitive.FastIntLongMap FastIntLongMap}, {@link javolution.util.primitive.FastIntFloatMap FastIntFloatMap}, {@link javolution.util.primitive.FastIntDoubleMap FastIntDoubleMap}, {@link javolution.util.primitive.FastIntObjectMap FastIntObjectMap}
  • long-keyed maps: {@link javolution.util.primitive.FastLongBooleanMap FastLongBooleanMap}, {@link javolution.util.primitive.FastLongByteMap FastLongByteMap}, {@link javolution.util.primitive.FastLongCharMap FastLongCharMap}, {@link javolution.util.primitive.FastLongShortMap FastLongShortMap}, {@link javolution.util.primitive.FastLongIntMap FastLongIntMap}, {@link javolution.util.primitive.FastLongLongMap FastLongLongMap}, {@link javolution.util.primitive.FastLongFloatMap FastLongFloatMap}, {@link javolution.util.primitive.FastLongDoubleMap FastLongDoubleMap}, {@link javolution.util.primitive.FastLongObjectMap FastLongObjectMap}

Architecture & Real-Time Predictability:

Unlike standard collections that allocate huge contiguous arrays or individual entry objects, {@code FastTable} allocates memory in small, fixed blocks of 1024 elements (Zero-GC fragmentation), while {@code FastSet} and primitive maps utilize high-dispersion open-addressing hash tables with linear probing directly over flat primitive arrays, reducing memory consumption by 80-90%.

Primitive Iterators and Views:

Iteration without boxing is supported via {@link javolution.util.primitive.FastPrimitiveIterator FastPrimitiveIterator} and specialized primitive iterator interfaces (such as {@link javolution.util.primitive.FastIntIterator FastIntIterator}); primitive maps expose {@code keyIterator()} and {@code valueIterator()} without allocating entry wrappers. In addition, every primitive table, set, and map supports thread-safe read-write locked live views (via shared()) and read-only live views (via unmodifiable()).
